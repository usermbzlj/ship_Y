## 一、用户的真实开发意图

这不是“给舰长多写几个提示词”或“再列一张工具清单”的任务。用户要求重构混乱的时间、决策和舰权体系，使它具备下面这些不可妥协的语义：

1. 世界时间必须连续、线性地推进。`XX/s` 表示每秒连续流逝 `XX` 世界秒，不得用大块跳时伪装推进。
2. 每到舰长设定的决策周期，世界必须精确停在截止点；先冻结时间，再把该时刻的信息交给舰长。部门咨询、舰长研判和设备命令完成前，世界时间不得偷跑，因此舰长拿到的不是延后信息。
3. 普通乘客等非阻塞活动应异步运行，不能因为后台 LLM 调用而冻结全世界。
4. 舰长应拥有现实舰长意义上的最高“世界内”权限：任务、部门、人事、乘客、安保、后勤、维修、传感器和舰体执行器都应能下令，并落到持久状态或真实设备层，而不是只生成文本。
5. **舰长绝对不能控制存档、读档、暂停/继续、时间倍率或上帝干预。**这些属于玩家/系统控制平面。该边界不能通过委派、部门会议或间接工具绕过。
6. 权力必须有因果约束：维修要消耗备件与工时，制造要消耗原料，气体和水要入账，设备受故障、供电和联锁限制；不能把“最高权限”实现成直接改写世界真值的魔法。

用户明确要求必须落地的舰长能力包括：改目的地/航线/任务目标、返航/改道/放弃；部门限时命令、回报、取消和变更；自主咨询与多轮会议；乘客公告/政策/申诉/外联；班次/岗位/负责人/调动；个人唤醒/休眠/治疗/分诊/转移/疏散；安保部署/门禁/拘留/调查/区域保护；食品/农业/货物/舱位/制造/备件替代；普通舱门和破口修复；散热器/热阀/氧气与气体/水分配；保护复位和维修重排；主动扫描、探测器和无人机；主要执行器及细分能量分配。

已经接入的真实效果：

- 改任务会修改聚合核心的权威航程，并更新运营任务方案；返航强制以原出发地为目的地，放弃任务进入 `stranded`。

- 安保门禁同时写入运营记录和实体舱门连接开度。
- 破口修复消耗密封材料，工时完成后才移除实体破口。
- 散热器和换热器控制直接修改冷却网络，并同步聚合热投影。
- 气体补充/回收同时改变分区气体质量和舰载储备，事务失败会整体回滚。
- A/B 制氧机按目标产率、生命保障馈线服务和净水余量连续生产；氧气、耗水和氢副产物质量分别入账，旧运营 `v1` 存档迁移后获得安全基线。
- 分区水额度会换算为 A/B 环按清醒人数加权的真实用水率；环间转运移动实体净水库存。
- 反应堆/断路器保护复位复用电力网络已有锁存复位命令，复位后仍处于安全状态。
- 维修网络支持取消、优先级和乘员/机器人改派；取消不自动退回已投入备件。
- 批准的备件替代会进入实际维修配方；替代件完工后写入持久降额，后续泵、空气处理机和水处理机指令受该上限约束。
- 部门命令和运营任务按值班人员、对应馈线与设备状态累计工时；定期回报保留准确边界时间，任务完成边界参与 Worker 公共切片。
- 人员转移先求解实体舱室连接路径，路径上的关闭、密封、受限或卡死连接会阻塞；安保调查建立案件、占用小队和工时并留下结论。
- 主动扫描按工时生成完成时刻物理报告；传感器频率写入相应实体传感器。
- 探测器/无人机部署和回收按工时改变状态；部署后消耗有限电池，停放时按舰载支持供电回充并生成遥测。
- 每负载功率上限写入运营域，并限制当前与后续动态控制需求。

## 五、已知缺口和不能夸大的部分

以下内容目前只是“有持久命令和因果纵切”，尚未达到完整舰船系统：

1. 部门命令和运营任务已绑定当前部门值班人员与对应馈线服务；尚未形成通用 DAG 任务图、跨部门资源竞争和技能矩阵。
2. 外部通信目前是舰务记录和送达时序，没有真实通信链路、带宽、距离延迟、对方回复或外交状态。
3. 人员转移/疏散已有逐舱最短路径与门/门禁/卡死阻塞；尚未模拟拥挤、担架搬运能力和多人争用同一通道。
4. `restricted` 门禁目前等效为物理关闭，没有身份认证和允许名单。
5. 安保调查已有案件、部署、受值班/供电影响的调查工时和结案记录；尚未模拟逐项证据、访谈对话和人员行为反馈。
6. 农业已绑定 A/B 生命保障供电、农业舱体积加权 CO₂ 分压（低于约 `10 Pa` 绝产、约 `40 Pa` 起满产）和可用净水；水按尝试生长消耗，食物按供电×CO₂ 因子产出。尚未细分光照、营养盐、作物生长阶段和病害。
7. 制造按数量消耗 `8 kg/件` 通用原料，按数量累计制造工时并受所属制造机环的工业馈线和工程值班约束；尚未细分不同配方、机床磨损和失败率。
8. 备件替代已进入实际维修配方并产生持久服务上限；现有物理域对替代件使用 `degraded` 工况与精确控制上限，尚未模拟每种替代件独有的失效模式。

10. 船体修复消耗密封材料，并受工程值班、破口所属环工业馈线和工时约束；尚未模拟舱外作业风险与损管机器人路径。

## 七、后续维护顺序

1. 先执行 `git status --short`，确认本文列出的脏工作树仍在；不要清理、重置或用远端覆盖。
2. 修改仿真后先跑对应的定向测试，再运行 `npm run check:docs`、`npm run typecheck`、`npm run lint`、完整 `node --test` 和 `npm run build`。
3. 扩展舰权时必须继续遵守控制平面隔离：不得把存档、读档、暂停、倍率或上帝干预加入舰长、部门或会议工具。
4. 后续 fidelity 优先级是：身份门禁允许名单与拥挤；外部通信链路；制造配方/机床故障；探测器连续轨迹与通信遮挡；真实星历和当前位置改道。
5. 真实云模型会议属于会产生外部调用的人工烟雾，运行前确认密钥和费用；默认自动测试只使用纯函数和假 `fetch`。
6. 当前用户没有授权提交或推送。若要提交，先整体审阅跨越时间/UI和舰权两轮的脏工作树，再由用户决定提交边界。
